Governing Philosophy

The doctrine of the
autonomous table

D.A.V.E. is not a gadget. It is an architectural stance: that a vessel's culinary sovereignty should not depend on harbours, fishmongers, or crew schedules. The system is built on a set of governing principles so thoroughly internalized that no single component needs to understand the whole. Each module operates as if communicating across a network boundary, even when running in the same housing. This is not engineering conservatism. It is engineering confidence.


The result is a system that fishes with the same disciplined autonomy with which you would delegate any high-value repeating task: define the mandate, set the constraints, and never think about it again.

PRINCIPLE 01 · ADR-002
External over Internal

Every subsystem treats its neighbours as remote entities, even at zero physical distance. Zero tight coupling means zero cascading failure. The galley does not care how the catch arrived. It cares that it did.

PRINCIPLE 02 · ADR-004
Offline-First Sovereignty

No satellite uplink. No cloud dependency. No marina-side subscription server that goes down at 03:00 in international waters. Every I/O path carries a degraded-mode fallback. When connectivity is unavailable, D.A.V.E. continues. The sea does not pause; neither should your dinner.

PRINCIPLE 03 · ADR-005
DELTA Contacts: Always Immediate

State changes to DELTA-classified contacts bypass all batching and hash-diff logic for immediate broadcast across the mesh. The system reacts before you have finished considering whether to react. This is what precision looks like at machine speed.

PRINCIPLE 04 · ADR-006
The Double-Fenced Loop Guard

CRDT propagation is governed by a double-fenced loop guard — enforced at both adapter and engine level simultaneously. The system cannot command itself into an uncontrolled state. Compounding engagement cascades are architecturally impossible, not merely policy-prohibited.

PRINCIPLE 05 · ADR-007
The Gate is Sovereign

No solenoid actuates without confirmed gate confirmation. This verification runs twice on every SUBDUE path, independently. You do not need to think about whether the system is safe in port. It is sovereign. The gate answers to no one but itself.

PRINCIPLE 06 · ADR-003
Policy-Driven Harvest Caps

Species-level ROE caps live in a hot-reloadable JSON policy store. Change what you are fishing for tonight without touching code. Want Mahi-Mahi only, no bycatch? Tell the policy. The mesh obeys. You drink your aperitivo undisturbed.

The Non-Negotiable

HUMAN
= Hard Stop

A species classification of HUMAN triggers immediate system-wide lockdown. All solenoid pathways terminate. All pod actuators hard-lock. All mesh nodes broadcast the halt simultaneously.

This behaviour is not configurable. It does not appear in the policy file. It does not have an override flag. It is not a feature — it is a covenant written directly into the architecture. Your divers, your guests, your crew surface safely, always.

IFF
BUGS Protocol — IFF Challenge / Response

Registered assets (crew, dive tenders, support craft) carry cryptographic IFF credentials. Authenticated contacts are excluded from engagement consideration before evaluation begins, not after. Zero risk of friendly-asset engagement.

GPG
GPG-Encrypted Asset Register

The crew and asset registry is GPG-encrypted at rest and never transmitted in plaintext. Identity resolution occurs locally, at the edge, within the vessel's sovereign mesh boundary. Your roster is not a cloud asset.

⊞
Offline Sovereignty Verification

On boot, the system verifies a locally-signed sovereignty manifest before any engagement capability is activated. An absent or tampered manifest forces civilian mode — no engagement, no exception. The system is honest about its own state.

▣
Hardware Tamper Detection

GPIO-wired tamper sensors monitor physical integrity of deployment hardware. Any detected tamper event halts engagement capability and logs the event to the immutable engagement log. The system watches for interference so you do not have to.

10-Step ROE Evaluation

The Harvest
Protocol

Before a single solenoid fires, D.A.V.E.'s Rules of Engagement evaluator conducts a ten-step adjudication sequence. Each step is a gate. Failure at any gate terminates engagement consideration cleanly, logs the disposition, and returns the system to surveillance posture. The galley gets only what the protocol approves.


This is not bureaucratic caution. It is the architecture's understanding that the value of a system is not in its aggression — it is in its precision.

Step 01
Human Classification Check

Unconditional. Species classifier result is verified against HUMAN. If matched: immediate hard stop. No further evaluation. No exception path.

Step 02
IFF Asset Resolution

Asset Register queried for registered contact identity. Authenticated allies are excluded from the engagement pipeline at source and flagged in the ledger.

Step 03
Species Classification Confidence

LLM classifier confidence score evaluated against policy minimum. Low-confidence classifications default to OBSERVE posture. The system does not guess.

Step 04
Policy Cap Verification

Species-level daily harvest cap consulted. If cap reached, engagement is suppressed. The system respects both your policy and the sea's carrying capacity.

Step 05
Gate Sovereignty Confirmation

Gate open state verified independently before engagement path is constructed. This is the first of two gate checks on the SUBDUE path.

Step 06
Swarm Behaviour Assessment

Multi-contact pattern analysis flags schooling behaviour for coordinated net deployment. Single-contact engagements route to speargun pods. The right tool, always.

Step 07
Engagement Level Selection

Engagement planner maps ROE verdict to the appropriate engagement level: OBSERVE / TRACK / SUBDUE. Proportionality is architectural, not advisory.

Step 08
Second Gate Confirmation

Gate sovereignty re-confirmed immediately prior to SUBDUE command dispatch. The second fence. The door is checked twice, every time, without exception.

Step 09
Command Registry Dispatch

Validated engagement command dispatched through the registry-based command handler. All state mutations are broadcast via hash-diff to the mesh simultaneously.

Step 10
Engagement Log Entry

Every engagement event — approved or suppressed — is written to the immutable SQLite engagement log. Full audit trail. The system is accountable to itself and to you.
